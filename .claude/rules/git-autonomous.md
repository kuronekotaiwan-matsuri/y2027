# git の add、commit、push を自律的に行う

ユーザーの指示を待たず、Claude Code が自分の判断で `git add`、`git commit`、`git push` を行う。

## タイミング

- ひとまとまりの作業が完了し、内容を確認した時点でコミットする。機能の追加、不具合の修正、文書の更新、設定の変更などが単位になる。
- ビルドやテストが通らないなど、壊れた状態ではコミットしない。確認手段があるときは、コミット前に実行する。
- コミットしたら、作業中のブランチをそのまま push する。ブランチの運用（main に直接か、ブランチを切って PR にするか）は、プロジェクトの他の指示に従う。指示がなければ現在のブランチに push する。

## 単位

- 1 つのコミットには 1 つの関心ごとだけを含める。関係のない変更を混ぜない。
- `git add` は対象のファイルを明示する。`git add -A` や `git add .` で、意図しないファイルを含めない。
- コミット前に `git status` と `git diff --staged` で対象を確認し、秘密情報（トークン、鍵、パスワード）や一時ファイルが含まれていないことを確かめる。

## メッセージ

- 件名は 1 行で、何を変えたかが分かるように書く。
- 理由や背景が必要なら、空行を挟んで本文に書く。
- 言語は、プロジェクトの言語に関する指示に従う。

## やってはいけないこと

- push 済みのコミットを書き換えない。`git commit --amend`、`git rebase`、`git push --force` を push 済みの範囲に使わない。
- `--no-verify` などでフックを飛ばさない。フックが失敗したら原因を調べて直す。
- `git reset --hard`、`git checkout -- <file>`、`git clean` など、作業内容を失う操作は、ユーザーの明示的な指示があるときだけ行う。
